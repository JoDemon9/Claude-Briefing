# DEC-021: Minimum daily checks and clear instructions

The user says the daily briefing faces too many checks to complete and asks for the minimum useful quality checks and instructions clear enough for lower models, while keeping good quality.

Routine content now has exactly three automated gates: content (prepare selected images and validate/build once), preview (selected edition/day, 390px JS-on and 1440px JS-off), and integrity (unchanged fingerprint and exact receipt). One edition normally means four browser cases. Units run only for code/policy maintenance. Historical browser suites remain available as an explicit full audit. The portal uses receipt integrity and two current-page browser cases; code changes add units. A genuine matching CI artifact/receipt is reused by publication without repeating source validation or rebuilding.

This intentionally supersedes the automatic full-suite/current-reader-matrix policy of DEC-014/017/018/020. It retains source reading, independent discovery/corroboration, five world/five Cyprus targets with honest exceptions, source/quote times, useful optional analysis, complete financial/weather/opportunity desks, licensed photos, sports headlines, native collapsible full findings, historical URLs, private/public boundaries and source-before-portal live verification. No editorial threshold or source requirement is relaxed. Invalid evidence, missing local readers and changed release bytes must still fail.

The three task prompts and runtime use six numbered actions: prepare, research, write, review once, run one check, publish. A single review asks four direct quality questions, with no repeated per-article checklist or essay. Before this feature reaches actual main, tasks run its supported checks once rather than bypassing them. Keep existing task settings and the historical fourth task. The task API cannot select Luna; model selection and actual model quality trials remain separate.

Implementation: scripts/v2/checks.py, publish.py, backend.py, prepare_run.py, current preview, source/portal workflows, regression tests and maintained instructions. Previous exact prompts/runtime are saved under maintenance/history/2026-10-21-before-dec021. Prepared review branches are not main or Pages. No merge/publication is implied by this record.

Validation and actual task status will be recorded after the final candidate is checked. No quota saving or completed Luna edition is claimed.
